# Playtest notes

One file per playtest session, numbered in order: `playtest-01.md`, `playtest-02.md`, and so on.

Each file keeps the notes **exactly as they were written during the session**, grouped by boss, followed by a status table recording what was actually done about each one. The notes are the record and don't get edited after the fact; the status table is what changes as work lands.

Status values used in the tables:

| Status | Meaning |
|---|---|
| **Done** | Built, verified, and in the branch |
| **In progress** | Being worked on now |
| **Queued** | Agreed, not started |
| **Design pass** | Being drafted for approval before any code or final art |
| **Won't do** | Deliberately not doing it — with the reason in the notes column |
